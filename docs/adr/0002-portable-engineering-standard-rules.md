# ADR 0002：工程标准规则抽离为可复用发行物，不再绑死 AIOS 自身仓库

日期：2026-10-22
状态：已确认（用户拍板；/grill 两轮收敛：第 1 轮定"归属与形态"，第 2 轮定"依赖方向进第一期"）

## 背景

工程标准本身已定义完整（`rex-harness/skill-sources/rex-engineering-standards/SKILL.md` §1–§7 + Definition of Done 九项），
但**机器门的归属搞错了**——能跑的三条全都只服务本仓库：

| 规则 | 现状 | 为什么外部用户用不上 |
|---|---|---|
| 目录条目 ≤8 | `scripts/check-dir-budget.mjs` | 引擎已是可注入的纯函数（`evaluateBudgets({budget, exemptions, baseline})`），但 `EXEMPT_DIRS` / `BASELINE_COUNTS` 是本仓库硬编码常量 |
| 单文件行数 | `evaluateArchitectureGovernance` + `rules/{components,lifecycle,rl}.mjs` | 24 条规则全是本仓库具体路径的 facade 护栏（19×80 行、5×320 行），不是通用预算；标准 §4 写的"约 400 行软上限"没有任何全仓库门 |
| 依赖方向 | `rex-import-boundaries`（父↔子模块双向） | 规则表达的是"AIOS 只能引 `rex-harness/src/index.mjs`"这一仓库形态，换仓库即失效 |
| DRY / 重复片段 | 无门 | 只在 `rex-code-review` 的 smell 基线（prompt 层） |

同时，规范文本的**送达**是软的：客户端读的是机器本地投影（`.agents/.claude/...`，gitignore），
本机投影由 rex-harness 0.5.0–0.7.0 生成而运行时已 0.11.1，66 条 rex 投影中 45 条与安装源码不一致；
且 `scripts/tests` 与 `rex-harness/tests` 里没有任何测试担保"四个 code-producing Provider 要求先加载标准"。

结论：规则的价值不在于它约束了 AIOS 自己的代码，而在于它能让每个使用 AIOS 的项目获得同样的判定能力。

## 决策

1. **统一模型：预算式规则（budget rule）**。一条可量化规则 = 一个度量 + 一个预算 + 三类处置
   （`exempt` 跳过并注明理由 / `baseline` 存量冻结只许收缩 / 其余超标即红灯）。
   这一模型直接沿用 `check-dir-budget.mjs` 已验证的形状，不另起一套。
2. **检查能力是 AIOS 发行物的一部分**：以一条 `aios` 子命令 + 非零退出码的形式提供，任何安装了 AIOS 的仓库都能敲；
   **不得要求调用方把检查脚本复制进自己仓库**。默认值随发行物走，项目侧只声明覆盖项与豁免理由。
3. **本仓库自身改为消费方**：AIOS 自己的 24 条 facade 规则、目录预算、`rex-import-boundaries` 双向门都迁到
   同一机制上，不允许双轨（否则"我们自己都不用这套东西"会立刻变成新的债）。
4. **前提条件**：规则文本必须先可靠送达（投影重生 + 漂移检测 + wiring 担保测试），否则再好的门也守着一个没人读的规范。

## 第一期范围（第 2 轮确认：依赖方向进第一期）

用户明确拍板：不只做量化预算类，**§1 依赖方向进第一期**。因此：

1. 需求输入面包含**分层声明**：项目声明哪些路径属于哪一层以及层序，供依赖方向判定使用。
   有解析器的仓库（JS/TS）走 import 图；无解析器的语言退回**路径前缀 + 引用字面量**近似，并在输出里标明是近似值。
2. 未声明分层时，依赖方向门输出 **SKIP 并说明原因**，不得猜分层——猜出来的架构违规比不查更坑
   （同 `AGENTS.md` 提示词规范第 1 条：代码只校验客观事实，不猜语义）。
3. 违规判定仍走预算式规则的三类处置：新违规即红灯，存量违规进 `baseline` 只许收缩。
4. 量化预算类（目录条目 / 单文件行数 / 裸日志 / 重复片段）与依赖方向共用**同一个命令、同一份配置面、
   同一个退出码口径**，不得裂成两个工具。

## 后果

- 需要一个项目侧配置面（承载预算、豁免理由、ratchet 基线）及其老化机制：冻结基线只许收缩，存量清掉后要能删条目。
- CI 红绿灯由项目自己接入；AIOS 只提供命令、退出码与结构化输出。
- 分层声明是新增的输入契约，配置面比"纯数数"大一截；换来的是非 JS/TS 仓库也能用到同一条门。
- `rex-import-boundaries` 泛化到新机制是决策 3 的推论；若它让工作量失控，回到本 ADR 重开裁决，而不是悄悄退回双轨。
- 送达（前提条件 4）必须先落地，否则本 ADR 的所有门都守着一个客户端读不到的旧文本。

## 归属边界（父仓库 / 子模块）

判据沿用 `docs/architecture/adr/0001-submodule-landing-boundary.md:30`：变更属于子模块，**当且仅当**它属于
"第三方可独立安装使用"的公开产品面（状态内核、契约、CLI、公开 schema）；其余留父仓库（适配层、编排、AIOS 集成）。
按这条判据重过一遍，原计划的落点定义如下修正：

| 工作项 | 落点 | 为什么 |
|---|---|---|
| 规则清单与默认预算（目录 8 / 单文件 400 / 重复阈值） | **子模块**，单一权威 | 它就是标准 §4–§6 的机器可读形式；第三方装 `@rexleimo/rex-harness` 就能拿到 |
| 度量引擎（预算 + exempt/baseline/new 三处置） | **子模块** | 纯客观度量，无 AIOS 集成知识；第三方可单独用 |
| 检查命令实现 | **子模块 CLI** | 公开产品面；子模块已有 `bin/rex-harness.mjs` 先例 |
| `aios standards check` | **父仓库**，只做转发 | 适配层；**禁止在父侧二次实现同一条语义** |
| 分层声明 schema | **子模块** | 公开 schema |
| 分层声明内容 + 存量规则迁入配置 | **父仓库** | AIOS 自身仓库的实例数据 |
| 投影生成与 `.rex-projection.json` marker | **子模块** | 已在子模块（`src/clients/projection-manifest.mjs`） |
| 升级时自动重生投影、`aios doctor` 漂移报告 | **父仓库** | AIOS 集成与 update 路径 |
| 「四个 Provider 必须第 0 步加载标准」的担保测试 | **子模块** | 测的是子模块自己的 skill-sources，不能只在下游仓库拦 |
| 本仓库私有门（`check-dir-budget.mjs` 常量、`rules/*.mjs` 24 条、`pretest:scripts`）退役 | **父仓库** | 消费方改造 |
| 外部真实仓库验收 | **不改代码** | 验证动作，两边同进 |

因此产生三条原计划没计入的后果：

1. 上表的子模块行都要走**子模块自己的发布流**（CHANGELOG + semver + tag，现 0.11.1），
   所以子模块侧改动必须批量化，不能一项一次 release。
2. **子模块指针移动是独立 commit**，不与功能改动混提（原 ADR 决策 2）。
3. 父侧 `aios standards check` 必须只 import `rex-harness/src/index.mjs` 或走进程调用，
   否则新增一条 deep-import 违规。
4. 默认预算的**单一权威在子模块**：需一条契约测试保证父侧默认值与子模块清单一致，不一致即红灯。
   （原计划写的是"默认值随 AIOS 发行"，那会把一条规则造成两个 owner——这正是本 ADR 要消除的缺陷。）

## 验收标准（用户可观察行为）

1. 在一个**不是 AIOS** 的仓库里，开发者只装了 AIOS 就能敲一条命令得到工程尺度报告；超标时退出码非零，
   输出逐条给出「文件/目录 : 度量值 : 预算 : 处置」，可直接贴进 PR。
2. 同一仓库里新写一个超预算文件（例如单文件超出行数预算）→ 立即红灯；拆到预算内 → 转绿，且不需要改 AIOS 安装物。
3. 存量超标项目第一次跑不把仓库刷成红：超标项自动进 `baseline`（只许收缩），报告写清基线与已收缩量。
4. 声明了分层映射时，新增跨层反向依赖（内层引外层）→ 红灯并指名是哪条引用；
   **没**声明分层时该门输出 SKIP + 原因，绝不拿猜测当违规。
5. 开发者能把这条命令放进自己的 CI，AIOS 不要求项目携带任何脚本副本。
6. 送达可验：`aios doctor` 能回答"本仓库的 rex 投影落后安装源码多少条"，
   且存在一个测试会在 Provider 不再要求先加载标准时变红。

## 度量口径与降级（work-config-surface C5）

- **口径唯一权威**：`QUANTITATIVE_STANDARD_RULES[*].measure`。引擎与门都按该字符串度量，项目侧不得自带第二份口径。
- **有 git 时**：以 `git ls-files` 的 tracked-file 列表为输入，按文件所在目录统计直接条目（文件与子目录各占一位）。未跟踪文件不计——新增未提交文件不会变红，提交后才受门（这是有意的：门管仓库状态，不管工作树）。
- **无 git / 非 git 目录时（目标行为，尚未实现）**：命令输出 `SKIP` 并给出原因（无法取得 tracked-file 列表），退出码 0。**不把未知当成违规**，也不用文件系统遍历猜一份口径——猜出来的红比没红更坏。
- **当前实测事实（2026-10-22）**：私有门 `scripts/check-dir-budget.mjs` 的目标根取的是**脚本自己所在的仓库**（`rootDir = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')`，第 109 行），不看 cwd。在任意非 git 空目录里跑它：退出码 0、报告 `767 dirs`，量的是 AIOS 本身。所以上面那条 SKIP 降级今天无从发生，而且验收 #1 / #5（外部仓库可用、能进别人的 CI）还差目标根解析——已写成 `work-budget-engine` 的完成标准，本节不得被当成已实现来引用。
- 需要覆盖未跟踪内容的场景，由调用方显式传入文件列表，而不是由命令改变默认口径。

## 非目标

- 不替项目引入平行的 lint / 格式化 / pre-commit 规范（标准 §6 原文："与仓库现有规范一致，不另起炉灶"）。
- 不做语义质量判定（"是不是薄转发""模块够不够深"）——仍由 Provider 与 review 轴负责，机器只数客观事实。
- 不改 `rex-engineering-standards` 的规则数值口径（只改它们如何被送达、被检查、被验收）。
- 不要求非 JS/TS 仓库提供 AST 级精度（标明近似即可）。
- 不在本需求里实现"自动拆文件"类修复动作。

## 第一个可验证切片

把 `check-dir-budget.mjs` 里的引擎（`countDirEntries` / `evaluateBudgets({budget, exemptions, baseline})`）
从本仓库常量中剖出，接上"项目侧配置 + 默认预算"，以 `aios` 子命令形式发布，
**并让 AIOS 本仓库自己改为调用这条子命令**（撤掉本地硬编码豁免/基线的特权）。

选它的理由：它已经有真机器门、真测试、真 ratchet 基线，是风险最低的一条；同一次改动可同时证明验收标准 #1 #2 #3 #5。
依赖方向门（#4）是**第二个切片**，因为它多一个输入契约（分层声明），不得混进第一个。

## 假设清单（`assumptions-recorded`，随交付可见）

- 分层声明采用**路径前缀 → 层名**的形态（与语言无关，比包名约定更 portable）；配置文件落点沿用项目侧既有习惯。
- 默认预算随 AIOS 发行（目录 8 项 / 单文件约 400 行），项目只声明覆盖项与豁免理由。
- "重复片段"度量在第一期允许是近似实现（先有可解释阈值 + 基线），不追求工具级精度。
- §6 工具链脚手架不作为本需求目标；若用户想翻这条，回本 ADR 重开裁决。
