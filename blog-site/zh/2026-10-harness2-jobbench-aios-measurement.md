# 我们让同一个 AI 模型，把同一份工作做了四遍

> **一句话版：** Google 的 [Harness²](https://github.com/google-research/harness2) 论文说，AI agent 的成绩，模型只占一小部分，大头在模型外面的 **harness**——工具、笔记、流程、反馈循环。我们在自己机器上复现了它的评测管线，挑了一个真实职业任务，让**同一个模型**在**四种工作环境**下各做一遍：得分从 68.2% 涨到 83.0%。

## 先讲道理：什么是 harness

模型是员工，harness 是他的**工位**：用什么工具、资料怎么摆、做错了有没有人让他复盘、有没有前辈把领域诀窍贴在桌上。Google 的主张是：不换人、只升级工位，产出就能明显变好。他们拿 JobBench 验证——从 35 种真实职业里抽出来的 65 个工作任务，不是脑筋急转弯，是分析师周二上班真会领的活。

论文里 JobBench 的提升幅度：**+4.5 分**。我们想要一个自己的数字。

## 我们怎么测的

任务：给一家虚构制造商做**运营效率分析**。输入是五个真实文件——客诉记录、工厂数据表、VP 备忘录；交付物是多 tab 分析簿加一份投资决策备忘录。这种任务人类预算约两小时。

四遍都换的是**环境**，不换的是**模型**（便宜的入门款 `agnes-3.0-flash`）：

1. **裸环境**：只给任务和文件。一个聪明员工，桌子全白。
2. **复盘改进**：先做一遍，让 harness 看着上一次的失败，把自己的说明书写得更好。桌上多了个复盘流程。
3. **领域注入**：把这类任务的门道提前整理进环境。桌上贴了前辈的便利贴。
4. **合并**：把两种改进合并，看会不会 1+1>2。

干活的、改环境的、打分的，全是同一个 `agnes-3.0-flash`，judge 用同一份评分细则、同一参数逐条打分。所以绝对分数没有跨管线意义——**四遍之间唯一的变量是环境，差值才是我们要的数**。

## 结果

| 环境 | 得分 | 对比裸机 |
| --- | ---: | ---: |
| 裸环境 | 68.2% | — |
| 领域注入 | 77.3% | +9.1 |
| **复盘改进** | **83.0%** | **+14.8** |

两个有意思的点：

- **流程胜过知识。** "从失败里复盘、重写自己的工作方法"的提升，是"塞领域知识"的近两倍，也是 Google 论文平均值的三倍。方向和 Harness² 完全一致——而且我们这边声音更大。
- **便宜模型根本不是瓶颈。** 同一个 flash 档模型，只是换了桌子，就从"及格"到"优秀"。如果你的 agent 在长任务上拉胯，先查它的工位，再考虑换脑子。

## 我们没在声称什么（这段最重要）

基准类文章最容易在这里作弊，所以直说：

- **只测了一个任务。** 方向是真的，幅度会在扩样本时移动。
- **打分模型和干活模型是同一个。** 自判偏好偏差存在；四遍共享同一 judge 同一参数能抵消一部分，但它是技术报告里排第一位的局限。
- **+14.8 和论文的 +4.5 不可并排比。** 不同模型、不同判法。我们只引用方向，不并排幅度。
- 这是 non-leaderboard 的自有环境测量，不是任何榜单成绩。

## 差点让复现翻车的三个 bug

给所有想在本地复现论文的人：

- 钉版客户端的 `baseURL` 少了个 `/v1`，请求其实打到了 404 页面——零输出、零报错。"能跑，但就是没东西"，最难查的一种死法。
- 一次卡死的模型调用占住了 agent 服务器唯一的会话槽，后面全部排队，整条 sweep 看起来像死了。
- 按量计费的通道欠费之后返回的是 **HTTP 200 + 空 body**，不是 403——"请求成功"完全骗人。现在我们花任何预算之前，探针必须验证**内容非空**。

**结论就一句：你的 agent 大概率是工位烂，不是脑子笨。先修工位，再掏钱换脑子——这次，数字是真的。**
