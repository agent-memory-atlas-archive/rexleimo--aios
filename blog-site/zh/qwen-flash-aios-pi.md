# 一句话需求，一件软件：小模型月烧 36 亿 token——AIOS 让"人人能做开发"成真

先说卖点：**AIOS 想做的事只有一件——让每个人都能做软件开发，只要你把需求描述清楚。**"会写代码"不再是入场券，"说得清楚"才是——而说清楚需求，是人本来就会的技能。

它的推论才是这篇的实测主角：你不需要旗舰模型，甚至不需要多贵的模型。过去一个月，我把 Qwen 3.8 Flash（中等思考档位）作为主力编码模型，跑在 Pi coding agent 里，外面套了一层 [AIOS](https://github.com/rexleimo/aios) 控制平面。结果是这套"小马拉大车"的组合，单月吞掉了 **36.28 亿 token**，缓存命中率 **96%**，交付了从宣传片渲染到多 Agent 并行发版的一整批真实项目。

一个月用下来的体感是：**这套组合的实战水平，已经能对标旗舰大模型 GPT-6 Sol 的境界**——模型小一号，成本降一档，但基本需求真的就是一句话丢过去，回来的是一个能跑、有测试、有证据的结果。

## 这些场景，眼熟吗？

- 40 分钟的长任务跑到第 18 分钟进程死了，你开了个新会话重新解释背景，它还是理解错了；
- 它说"做完了"，你打开一看，测试没跑、功能不在；
- 旗舰模型很聪明，但它的价格不支持你 24 小时挂着跑；
- 小模型便宜又快，但你不敢把重要活交给它——因为它转头就忘。

只要中了一条，你缺的就不是更大的模型，而是一层控制平面。下面是我用 AIOS 把一个小模型变成"值得托付"的完整证据——截图、仓库、项目，都可以查。

## 你需要的新技能只有一个：把需求说清楚

软件开发的历史门槛一直是"会写代码"。AIOS 把门槛改写了：从"会写代码"变成"会描述需求"——后者不需要学，它本来就是你的母语。但有一个前提：**得真的说清楚。**

AIOS 不赌你"恰好说清楚了"，它把"说清楚"本身做成了产品能力：

- **需求澄清（`/grill` + Ask-First）**：你说"做个下载工具"，它不会直接开写——先查仓库和历史决策，再一次只问你一个决策性问题（鉴权方式？存储位置？），带假设提问、3 轮内收敛，把模糊需求磨成可验收的规格；
- **工作流分档（direct / guarded / planned）**：一句话的小修直接办，多步的大活先出一份你能看懂的计划再开工——你永远知道它在干什么；
- **完成前证据门禁**：想对你说出"做完了"三个字，必须先过测试、diff、截图这些硬证据——它骗不了你；
- **跨会话记忆**：今天没说完的需求，明天它还记得，说"继续"就真的继续。

完整流程长这样：你说"我想要一个油管解析下载工具，前后端分离"→ AIOS 反问两个决策性问题 → 路由到计划档开工 → 并行派发实现 → 测试和截图作为证据交付。你全程只做了两件事：**描述需求，和回答两个问题。**

下面每一个数据、每一个项目，都是这条流程的产物。

**项目记忆（`.aios/memo/`）**。每个里程碑自动钉成 checkpoint，"验证：pnpm test 全绿 + typecheck/lint 全过"就写在旁边——这就是"说继续，真的能继续"背后的东西。

![真实会话截图：模型自己调用 aios_memory_write 把踩坑结论钉进记忆，返回 memo 事件 ID](../assets/qwen-flash-aios/shot-live-memory.png)

**实时写入（上一张正在发生的样子）**。任务做到一半，模型判断"Dockerfile 运行阶段只 COPY 白名单脚本"是个会反复踩的坑，自己调用 `aios_memory_write` 钉进项目记忆，落盘即返回事件 ID。没有人要求它记——**它决定记**。这才是记忆系统真正的形态：不是查表，是习惯。

![证据封套：sha256 哈希、accepted 状态、非回归标志，机器可复核](../assets/qwen-flash-aios/shot-evidence.png)

**证据封套（`docs/evidence/`）**。做没做完，由哈希说了算，不由嘴说了算：baseline/candidate 的 contentSha256、非回归标志、验收状态，全部机器可复核。"完成前证据门禁"不是修辞，就是这类 JSON。

## 裸模型 vs 套上 AIOS：同一匹马，两种拉法

下面是这一个月里，同一类任务在"裸 Pi + Qwen 3.8 Flash"和"Pi + Qwen 3.8 Flash + AIOS"下的实际体感对比（个人日常使用观察，非受控基准，样本就是我自己每天的活）：

| 维度 | 裸模型工作流 | + AIOS 控制平面 | 变化 |
| --- | --- | --- | --- |
| 跨会话续做 | 每次重新解释项目背景，经常猜错上次的进度 | 记忆召回 + 检查点恢复，说"继续"就真的继续 | 返工大幅减少 |
| 长任务存活率 | 中途断一次，上下文全丢，从头再跑 | 每步落检查点，进程被杀也能接着跑 | 过夜任务可恢复 |
| 任务完成率 | 复杂多步任务经常"看起来做完了" | 声称完成前强制过证据门禁（测试、diff、截图） | **相对提升约 40%** |

"约 40%"这个数是宣传口径，我认。但它的锚点很激进：在这套组合下，小模型的日常交付水平可以直接对标 GPT-6 Sol 的境界。为什么敢这么说？背后有个可验证的机制：**小模型的失败模式不是"想不对"，而是"忘了、偏了、没验证就交"**——这三类失败恰好全部是控制平面负责解决的。把环境错误率压下去，小模型的原始能力利用率就上来了。这也是为什么同样的模型，在这套组合里"像换了一个"。

## 在 Pi 里怎么跑起来

三步，全部本地运行，数据不出机器：

```bash
# 1. 安装 AIOS（Windows 用 irm 一行，见 README）
curl -fsSL https://github.com/rexleimo/aios/releases/latest/download/aios-install.sh | bash

# 2. 在项目根目录初始化，会自动识别 Pi 并装上原生增强
cd your-project
aios init --all
aios doctor --native --verbose

# 3. 把 Qwen 3.8 Flash 配成 Pi 的模型（OpenAI 兼容端点，具体格式以 Pi 官方文档为准）
pi   # 选择/指定 qwen3.8-flash，然后正常开工
```

之后你的日常就变成了：在 Pi 里正常对话，AIOS 在外围接管记忆召回、工作流分档（direct / guarded / planned）、完成前证据验证。不需要改任何使用习惯——**Agent 还是你的 Agent，模型还是你的模型，AIOS 只是把"环境"补齐了。**
