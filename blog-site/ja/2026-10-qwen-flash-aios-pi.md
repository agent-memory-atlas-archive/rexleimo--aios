# 一文の要件で、一つのソフトウェアを：小規模モデルが月36億トークン——AIOS が「誰でも開発できる」を現実のものにする

セールスポイントから：**AIOS がやりたいことは一つだけ——要件を明確に記述できる人なら、誰でもソフトウェア開発できるようになること。**「コードが書ける」はもう入場券ではない。「言い切れる」が入場券だ——そして要件を語り切ることは、人間が元から持っているスキルだ。

その帰結として本題の実測がある：フラッグシップモデルは不要。そもそも高価なモデルすら要らない。過去1か月、Qwen 3.8 Flash（中程度の思考レベル）を主力コーディングモデルとして Pi coding agent で動かし、その外側に [AIOS](https://github.com/rexleimo/aios) コントロールプレーンを1枚かぶせた。この「小馬で大車を引く」構成は、1か月で **36.28億トークン** を消費し、キャッシュヒット率 **96%**、プロモ動画のレンダリングからマルチエージェント並列リリースまで、実プロジェクトの一揃いを納品した。

1か月使った実感：**この構成の納品レベルは、フラッグシップ大規模モデル GPT-6 Sol に堂々と対標できる**——モデルは一回り小さく、コストは一段低い。それでも基本要件は本当にワンセンテンス放り込むだけで、動く・テスト済み・証拠付きの結果が返ってくる。

## この光景、覚えはないか？

- 40分の長時間タスクが18分目で死に、新しいセッションで背景を説明し直しても、やはり的外れ；
- 「完了」と言うので開けると、テストは走っておらず機能も存在しない；
- フラッグシップモデルは賢いが、その価格では24時間回し続けることはできない；
- 小規模モデルは安くて速いが、セッションをまたぐと忘れてしまうので、重要な仕事を預けられない。

一つでも当てはまったなら、あなたに足りないのはもっと大きなモデルではなく、コントロールプレーンだ。AIOS が小規模モデルを「任せてよい存在」に変える完全な証拠を以下に示す——スクリーンショット、リポジトリ、納品済みプロジェクト。すべて検証可能だ。

## 必要なのはたった一つの新しいスキル：要件を明確に語り切ること

ソフトウェア開発の歴史的な入場券は「コードが書けること」だった。AIOS はその門番を書き換える：「書ける」から「言い切れる」へ——後者は学ぶ必要すらなく、元からあなたの母語だ。ただし前提がある：**本当に明確に言い切れていること。**

AIOS はあなたが「たまたま明確に説明した」ことに賭けない。「明確さ」そのものを製品能力にした：

- **要件ヒアリング（`/grill` + Ask-First）**：「ダウンロードツールを作って」と言えば、すぐ書き始めることはしない。まずリポジトリと過去の決定を照会し、決定事項を一度に一つだけ質問してくる（認証方式？保存先？）。仮定を添えた質問で3回以内に収束し、曖昧な要望を検収可能な仕様へ磨き上げる；
- **ワークフローの3段ルーティング（direct / guarded / planned）**：一言で済む修正はそのまま実行。多段の大きな仕事は、あなたが読める計画を1枚出してから着工——何が起きているか常に分かる；
- **完了宣言前の証拠ゲート**：「完了」と言う前に、テスト・diff・スクショという硬い証拠を通過させる——ごまかせない；
- **セッションをまたぐ記憶**：今日語り切らなかった要件を、明日も覚えている。「続けて」は本当に続く。

完全な流れはこうだ：「フロント/バックエンド分離の動画解析・ダウンロードツールが欲しい」と言う → AIOS が2つの決定事項を聞き返す → planned にルーティングして着工 → 並列ディスパッチで実装 → テストとスクショを証拠に納品。あなたが全過程でやったことは二つだけ：**要件を語り、質問に二つ答えたこと。**

以下すべての数字とプロジェクトは、この流れの産物だ。

## 証拠は形容詞ではない：リポジトリ内部のアーティファクト

以下の3枚はすべてリポジトリ内の実ファイル由来で、内容は自由に照合できる：

![ADR 意思決定記録：確定した決定はリポジトリに書き込まれ、「上流のリネームに追随しない」ですら出典を持つ](../assets/qwen-flash-aios/shot-adr.png)

**ADR 意思決定記録**。要件ヒアリングは聞いて終わりにならない。確定した決定は `docs/architecture/adr/` にリアルタイムで書き込まれる——「CONTEXT.md を維持し、上流のリネームには追随しない」という裁決すら、原文・日付・帰結分析を備えている。セッションをまたいで「方針が変わっていた」ことを防ぐのはこれだ。

![プロジェクト記憶のチェックポイント：マイルストーンごとにピン留め、検証行がすぐ脇に書かれている](../assets/qwen-flash-aios/shot-memo.png)

**プロジェクト記憶（`.aios/memo/`）**。マイルストーンごとに checkpoint として自動ピン留めされ、「検証：pnpm test 全緑 + typecheck/lint 全通過」がすぐ脇に記される。「続けて」が本当に続く裏側の仕組みがこれだ。

![実セッションのスクリーンショット：モデル自ら aios_memory_write を呼び、踩坑の教訓をプロジェクト記憶にピン留めし、memo イベント ID を受け取る](../assets/qwen-flash-aios/shot-live-memory.png)

**リアルタイムでの書き込み（前出の記憶が生まれている瞬間）**。タスクの途中で、モデルは「Dockerfile の実行段階はホワイトリスト入りスクリプトのみ COPY する」という繰り返して踏む落とし穴を判断し、自ら `aios_memory_write` を呼びプロジェクト記憶にピン留め、書き込みと同時にイベント ID を受け取った。誰も覚えろとは言っていない——**それが覚えることを決めたのだ**。記憶システムの本当の姿はこれだ：引表ではなく、習慣である。

![証拠封包：sha256 ハッシュ、accepted 状態、非回帰フラグ、すべて機械照合可能](../assets/qwen-flash-aios/shot-evidence.png)

**証拠封包（`docs/evidence/`）**。やり切ったかどうかは、言葉ではなくハッシュが判定する：baseline/candidate の contentSha256、非回帰フラグ、受入状態——すべて機械的に再計算可能。「完了前の証拠ゲート」は修辞ではなく、この JSON のことだ。

## 感覚の前に、データを見よう

![直近30日のモデル使用量：総トークン 3627.97M、キャッシュヒット率 96%](../assets/qwen-flash-aios/token-usage-30d.png)

このスクリーンショットは使用量パネルのそのままの姿で、加工は一切ない：

- **総トークン数：3627.97M**——1か月分、すべて日常の実開発。ベンチマークの水増しではない；
- **キャッシュヒット率 96%**（3459.56M / 3604.78M の入力がヒット）——コンテキストを極限まで再利用。これこそが小規模モデルで大プロジェクトを回せる鍵；
- 1日あたりのピーク **263.43M トークン**（9/16）、1.6億超えが連日——高強度・長時間セッション・途切れなし。

この 96% はモデルが稼いだものではない。AIOS の層が稼いだものだ：プロジェクト記憶の常駐、プル型コンテキスト取得、重複注入を削り落とすトークン圧縮インターセプション層。モデルは「考える」だけ、環境が「聞き直さない」を引き受ける。

## むき出しのモデル vs AIOS で包む：同じ馬、違う鎧

以下は1か月の日常使用で、同種のタスクを「むき出しの Pi + Qwen 3.8 Flash」と「Pi + Qwen 3.8 Flash + AIOS」で比較した体感データ（個人の日常観察であり、管理されたベンチマークではない。サンプルは自分の日々の仕事そのもの）：

| 観点 | むき出しのモデル運用 | + AIOS コントロールプレーン | 変化 |
| --- | --- | --- | --- |
| セッションをまたぐ続行 | 毎回プロジェクト背景を再説明、前回の進捗を推測して外す | 記憶召回 + チェックポイント復元、「続けて」が本当に続く | 手戻りが大幅減 |
| 長時間タスクの生存率 | 途中で一度切れたら全文脈消失、ゼロから再実行 | 各ステップにチェックポイント、プロセスを殺されても再開できる | 徹タスクが復可能に |
| タスク完了率 | 複雑な多段タスクが「見た目は完了」で終わりがち | 完了宣言前に証拠ゲートを強制（テスト・diff・スクショ） | **相対向上 約40%** |
| 1タスクあたりのコスト | コンテキストの重複注入でトークンを浪費 | キャッシュヒット96% + オンデマンドコンテキスト | 実効コストが明確に低下 |
| マルチエージェント協働 | なし | `aios work` 1コマンドで並列ディスパッチ・マージゲート付き | ゼロからイチへ |

「約40%」は宣伝の数字だ、と認めておく。ただしアンカーは攻めている：この構成なら小規模モデルの日常納品レベルはGPT-6 Sol に直接対標できる。なぜ言い切れるのか？検証可能なメカニズムがある。**小規模モデルの失敗モードは「考えられない」ことではなく、「忘れる・逸れる・検証せずに納品する」こと**——この3種類の失敗はちょうどコントロールプレーンが担当する領分だ。環境側のエラー率を下げれば、モデルの元々の能力の利用率が上がる。同じモデルなのに「取り替えたように」見えるのはこのためだ。

## この構成が実際に作り上げたもの

デモではない。実際に納品され、証拠が確認できるプロジェクト群だ。最も直接的な証拠は私の `E:/coding` ディレクトリ——**以下のプロジェクトはすべて Pi + Qwen 小規模モデル + AIOS という同一構成で書かれた**もので、どのプロジェクトの起点もワンセンテンスの要件だった：

| プロジェクト | 中身 |
| --- | --- |
| **aios-pro** | local-first のデスクトップエージェントハーネス。実ワークスペース上のオーケストレーション層 |
| **inkloom.im** | ビジュアル AI クリエイティブワークフロー基盤。再現可能な AI 画像/動画パイプライン |
| **huabu** | キャンバス制作 + 画像・動画ワークベンチ + 転描プロジェクトとアセット管理 |
| **rex-ai-tools** | フロント/バックエンド分離の動画解析・ダウンロードツール |
| **discourse-worker / services** | フォーラムワーカーと ingest / user-center / webui マイクロサービス |
| **rex-hugo / rex-videos** | コンテンツサイトの公開パイプラインと AI 動画制作スキル群 |
| **claude-relay-service / vpn-master / hermes-setup / xsapp** | リレー・デプロイ・インストーラ・アプリ系のエンジニアリング |

プラットフォーム級の製品（inkloom、aios-pro）から、クリエイティブワークベンチ（huabu）、コンテンツパイプラインやフォーラムマイクロサービス、デプロイ運用まで——要件整理、アーキテクチャ、コーディング、テスト、デプロイの全過程で大規模モデルに乗り換えていない。これが「ワンセンテンスで基本要件を済ませる」の現実版だ：**あなたの発話が短くなったのは、環境が長いタスクを受け止めているから。**

証拠チェーン付きのサンプル事例を3つ：

**1. AIOS プロモ動画：カット単位並列ディスパッチ、1355フレーム完全レンダリング**

Remotion のプロモ動画をカットごとに独立した作業項目へ分解し、複数の小規模モデルエージェントが並列で各シーンを生成。メインスレッドは共有コンポーネントを凍結し、最終的な完了判定は実際のレンダリングログが担った。45秒の完成動画、1355フレーム、レンダリング426秒完了——「大規模モデル」は1つも関わっていない。

**2. マルチクライアントのコントロールプレーンそのもの**

AIOS は現在10個のコーディングクライアントをサポート——Codex CLI、Claude Code、Gemini CLI、OpenCode、Hermes、Grok、WorkBuddy、**Pi**、ZCode、Qoder。このクライアント横断の適配、記憶システム（memo/ContextDB）、RL 学習システム、v5.6.0 の `aios work` 並列ディスパッチは、すべて小規模モデル + コントロールプレーンの反復で生まれた。

**3. 日常運営の自動化**

小紅書（RED）3アカウントのコンテンツキュー + ブラウザ自動化運営。毎日2時間から15分へ短縮（[実録記事](xiaohongshu-automation.md)参照）——実行は小規模モデル、レビューポイントは人間、環境が越境しないことを保証する。

## Pi での動かし方

3ステップ、すべてローカル実行。データは機械の外に出ない：

```bash
# 1. AIOS をインストール（Windows は irm 1行、README 参照）
curl -fsSL https://github.com/rexleimo/aios/releases/latest/download/aios-install.sh | bash

# 2. プロジェクトルートで初期化。Pi を自動認識してネイティブ拡張を導入
cd your-project
aios init --all
aios doctor --native --verbose

# 3. Qwen 3.8 Flash を Pi のモデルとして設定（OpenAI 互換エンドポイント。書式は Pi 公式ドキュメント準拠）
pi   # qwen3.8-flash を選択/指定して、いつも通り仕事する
```

以降の日常は変わらない：Pi に普通に話しかけ、AIOS が外側で記憶召回、ワークフローの3段階ルーティング（direct / guarded / planned）、完了前の証拠検証を引き受ける。使用習慣の変更は不要——**エージェントはあなたのエージェントのまま、モデルはあなたのモデルのまま。AIOS が「環境」を埋めるだけだ。**

## 最後に

1か月36億トークンを燃やして得た最大の教訓：「小規模モデルで十分賢いか」を尋ねるのをやめ、「あなたの環境は、モデルが既に持つ賢さに値しているか」を尋ねよ。モデル能力は掛け算の被乗数、コントロールプレーンは乗数だ——乗数を1から1.4にすれば、被乗数があの小柄な馬のまま、GPT-6 Sol のペースが出る。
