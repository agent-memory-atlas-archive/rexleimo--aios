# 自社のトークン圧縮を実測した：AIOS Token Bench 初のA/B結果

> **一言でいうと：** 圧縮の節約効果を議論するのをやめ、測定に移った。凍結された 8 タスクのベンチで（モデルを固定し）、新しく導入した Pi 観察オフロード機構（オフ → オン）の A/B ペアを 3 組実行した。トークン節約は 2 ペアで +16% と +21%、3 番目のペアで **−64% に反転**——平均は −4%——理由は、モデルが大型読み取りタスクで余分なリトリーブ・ターンを重ねることがあるため。コストは平均 21% 減だが分散は同じ。だから正直な見出しは：対象タスクはしばしばトークンを半減させ、機構は自らの 2 ゲート規律に従い **opt-in（デフォルト オフ）で出荷する**、分散が次の工学的課題である。以下の数値はすべて 3 つのコマンドで再現できる。

## 議論ではなく測定をする理由

NVIDIA の SoL-Pi は自動研究ループと凍結された held-out ベンチマークにより、152 の候補機構を 4 つに絞り込んだ。我々は彼らのパッケージを評価し、Pi の安全ゲートおよび管理トランスポートとの構造的競合を 2 つ発見し、結局一行も導入しなかった——しかし、その規律は丸ごと借りた：

1. **凍結タスクセット**：受け入れ専用。チューニングには決して使わない。
2. **統合台帳**：すべてのトークンイベントをレイヤー・タスク・モデルに帰属させる。
3. **2 つの受け入れゲート**：能力チェックに合格し、実測節約が正であること——さもなければ機構は opt-in のまま。

## ベンチの姿

AIOS token bench はリポジトリ内にある：8 つの凍結タスク（エコー、JSON 契約、シェル往復、小/大ログ読み取り、複数ターンの書き込み+実行）を、管理対象 Pi RPC トランスポートで実行し、モデルは `kimi-k2.7-code` に固定。毎ターンの使用量——入力、出力、キャッシュ読み、コスト、停止理由——がタスク id 付きで台帳に流れ込む。

```bash
node scripts/token-bench/run.mjs --dry --json   # 凍結セットを検証、クライアントは起動しない
node scripts/token-bench/run.mjs --session bench-ab-off --model <provider/model>   # 実跑、実際のトークンを消費
node scripts/token-bench/compare.mjs --a bench-ab-off --b bench-ab-on              # A/B レポート
```

## 最初の A/B 結果

同じタスク、同じモデル、変数はひとつ：観察オフロード機構のオフ対オン。3 ペアのうちの 1 ペア目。

| タスク | オフ·ターン | オン·ターン | オフ·tokens | オン·tokens | Δ tokens |
| --- | --- | --- | --- | --- | --- |
| bench-001 エコー | 1 | 1 | 16,548 | 16,559 | +11 |
| bench-002 シェルバージョン | 2 | 2 | 33,210 | 33,229 | +19 |
| bench-003 小ログ読み取り | 2 | 2 | 33,531 | 33,787 | +256 |
| bench-004 ERROR 行数 | 3 | 2 | 53,465 | 35,070 | −18,395（−34%） |
| bench-005 JSON 契約 | 1 | 1 | 16,566 | 16,578 | +12 |
| bench-006 算術コマンド | 2 | 2 | 33,254 | 33,239 | −15 |
| bench-007 大ログ読み取り（126 KB） | 4 | 2 | 67,500 | 34,316 | −33,184（−49%） |
| bench-008 複数ターン書き+実行 | 3 | 3 | 50,272 | 51,570 | +1,298（+3%） |
| **合計** | | | **304,346（$0.1035）** | **254,348（$0.0602）** | **−49,998（−16%）** |

## 数値が実際に語ること

**対象の形状は設計どおりに反応した。**bench-007 は約 126 KB のツール観察をコンテキストに強制投入する。機構オンでは、この観察は一度だけアーカイブされ、コンテキストにはハンドルと要約だけが残る。モデルは必要な行だけを正確にページバックする。このタスクのトークンは 49% 減、ターンは 4 から 2 に収束した。

**コストはトークンより速く下がる。**合計トークンは 16% 減だが、実測コストは 42% 減。オフアームの余分なターンは、キャッシュされていない大きな入力を最も高いレートで再課金していた。ターンが減ることで、より多くの消費がキャッシュ読みに移る。トークンを最適化すればその一部を得られ、ターンを最適化すればすべてを得られる。

**小さなタスクはノイズ帯であり、それ自体が結論である。**ツールを使わないタスクは約 16K トークンのコンテキストフロア（システムプロンプト＋ハーネスベースライン）を背負っており、どのオフロード機構もこれには触れない——以前のベースラインではこのフロアが総消費の 59% を占めた。オフロードはフロア対策のレバーではなく、フロア数値の存在意義はこの境界を明確にすることだ。

## 残り 2 ペアが示したこと

デフォルトオンの判断の前に 3 組の繰り返しペアを取ると約束した。それが物語を変えた：

| ペア | オフ·tokens | オン·tokens | Δ tokens | Δ コスト | bench-007 オフ → オン |
| --- | --- | --- | --- | --- | --- |
| 1 | 304,346（$0.1035） | 254,348（$0.0602） | −16% | −42% | 67,500 → 34,316（4→2 ターン） |
| 2 | 338,064（$0.0982） | 268,559（$0.0585） | −21% | −40% | 120,284 → 67,432 |
| 3 | 237,685（$0.0551） | 389,675（$0.0837） | **+64%** | **+52%** | 36,240 → 172,992（10 ターン） |
| **平均** | 293,365 | 304,194 | **−4%** | **−21%** | |

ペア 3 は反転した。ターンごとの台帳が理由を正確に示す：オンアームの bench-007 は **2–4 ではなく 10 ターン**実行されたが、各ターンのコスト構造は正常（同じ約 16K のフロア、健全なキャッシュ読み）——モデルはなかなか収束せず、観察を繰り返しページバックした。機構の故障ではない；まさに機構が狙うタスクにおいて、モデルのリトリーブ方針が高分散だったのだ。

そこから 2 つの正直な結論。第一に、3 ペアのコスト平均は依然 21% 減で、モデルが速く収束した 2 ペアでは機構は設計どおりに動いた——しかしトークン平均 −4% は安定した勝利ではない。第二に、自らの 2 ゲート規律に従い、**機構は opt-in で出荷する（デフォルト オフ、`AIOS_PI_OFFLOAD=on` で有効化）**。分散に工学的答えが出るまで：タスクごとのリトリーブ予算を設け、超過すればハンドルは単なる「アーカイブ過大」ポインタに退化する。

## それでも主張しないこと

- **平均は安定した勝利ではない。**3 ペアのトークン平均 −4% はゼロの分散内。コスト平均（−21%）はより良いが、同じ 3 回のサイの目に依存している。
- **オンアームで 1 回チェック失敗**（ペア 1 のオンアームで bench-007 の応答が期待した id を漏らした）。同機構同モデルの単独再実行では正確に命中。モデルの分散と判定し、機構の損傷ではない——しかし記録には残す。「偶発、無視」のファイルには入れない。
- **トークン数値はランタイムの usage 報告に基づく**、プロバイダの請求書ではない。以下の 3 ヶ月台帳の数値はバイト推定（bytes ÷ 4）。
- **モデルはひとつ。**バックエンドを変えれば、パーセンテージは大きく動きうる——リトリーブ・ターン分散そのものも含めて。

## 背後の 3 ヶ月台帳

A/B は新しいが、記帳はそうではない。refs レイヤー——オーケストレータ境界で超大きなツール出力をオフロードするレイヤー——は 6 月から全イベントを記録してきた。本稿時点で：**2,552 イベント、推定 raw 5.73M トークンのうち 5.43M がコンテキスト外に保持（94.8%）**、制御外イベントゼロ、ポリシー違反ゼロ。最多は MCP ツール結果（1,768 イベント）とツール一覧（578）。`aios tokens report` がこれをレイヤー別・セッション別に表示する。

## 機構そのもの、一段落で

`ObservationPack-lite` は AIOS Pi 拡張に同梱して出荷される。**デフォルトはオフ**（`AIOS_PI_OFFLOAD=on` で有効化）。Pi の `context` イベント（毎回の LLM 呼び出し前に発火）で、20K 文字以上のテキスト観察はワークスペース状態ルート下のコンテンツアドレス指定ファイルに一度だけアーカイブされ、コンテキスト内のコピーは 16 桁の 16 進 ref・行数/バイト数・先頭と末尾の要約に置き換えられる。読み取り専用の `aios_offload_retrieve` ツールが ref と行範囲で原文をページバックする。ツール実行には触れないため安全ゲートとの相互作用はない。

## これからの規律

機構がデフォルトオンで出荷される前に、凍結ベンチ上の両ゲートを通過すること：能力は許容差内、節約は実測で正——しかも幸運な 1 回ではなく、繰り返しペアにわたって安定して。ObservationPack-lite は、そのリトリーブ・ターン分散に工学的答え（タスクごとのリトリーブ予算が自明な候補で、ベンチはまさにそれを検証するために存在する）が出るまで opt-in のまま。ベンチは実際のタスク履歴から拡充し、台帳が証憑を保持し、本稿以降、このブログ上のすべての主張は他人が実行できるコマンドであるべきだ。
