# 같은 AI 모델에게 같은 일을 네 번 시켜 봤다

> **한 줄 요약:** Google [Harness²](https://github.com/google-research/harness2) 논문은 agent 성적을 모델보다 **harness**(도구·노트·프로세스·회고 루프)가 결정한다고 말한다. 우리는 평가 파이프라인을 자체 머신에 재현하고, 실제 업무 태스크 하나를 **같은 모델**로 **네 가지 환경**에서 각 한 번씩 돌렸다: **68.2% → 83.0%**.

## 원리

모델은 직원, harness는 **책상**이다 — 도구, 자료 정리, 실수 후 회고, 선배의 메모. Google의 주장: 사람을 바꾸지 않고 책만 업그레이드해도 성적이 오른다. 검증은 JobBench — 35개 직종에서 가져온 65개 실제 업무(퀴즈가 아니라 화요일에 분석자가 받는 일). 논문 향상폭은 **+4.5**. 우리는 우리 숫자가 필요했다.

## 측정 방법

태스크: 가상의 제조사 **운영 효율 분석**. 입력은 실제 파일 5개(고객 클레임·공장 데이터·VP 메모), 산출물은 멀티탭 분석 워크북 + 투자 메모. 인간 예산 약 2시간.

네 번 모두 **모델 동일**(저가 `agnes-3.0-flash`), 바뀌는 건 **책상**뿐:

1. **맨 책상**: 태스크와 파일만.
2. **회고 개선**: 첫 시도의 실패를 보고 harness가 자기 지시문을 다시 쓴다.
3. **지식 주입**: 도메인 요령을 사전에 환경에 심음.
4. **융합**: 두 개선책 합체.

작업자·개선자·채점자 전부 같은 agnes, 같은 루브릭·같은 파라미터. 절대점은 안 넘겨진다 — **네 번 중 유일한 변수는 책상이므로, 차이가 곧 측정값**.

## 결과

| 책상 | 점수 | 맨 책상 대비 |
| --- | ---: | ---: |
| 맨 책상 | 68.2% | — |
| 지식 주입 | 77.3% | +9.1 |
| **회고 개선** | **83.0%** | **+14.8** |

- **프로세스가 지식을 이겼다.** 폭은 지식 주입의 약 2배, 논문 평균의 약 3배. 방향은 Harness²와 정확히 일치, 우리는 더 크게 나왔다.
- **저가 모델이 병목이 아니었다.** flash급 그대로 책상만 바꿔 낙제→우수. agent가 장기 태스크에서 밀리면, 두뇌 교체 전에 책상을 의심하라.

## 주장하지 않는 것

- **n=1.** 방향은 진짜, 폭은 표본 늘리면 움직인다.
- **채점자=작업자 모델.** 자기선호 편향 존재. 네 번이 같은 judge라 상대 Δ는 상쇄되지만 기술 리포트 1순위 한계.
- **+14.8과 논문 +4.5는 나란히 못 놓는다.** 모델·채점 방법 다름. 방향만 인용.
- non-leaderboard 자체 환경 측정.

## 재현을 거의 엎은 버그 3개

- `baseURL`에 `/v1`이 빠져 요청이 404 페이지에 닿음 — 출력 0, 에러 로그 0. "돌아가는데 결과 없음", 가장 찾기 어려운 죽음.
- 행방불명된 모델 호출 하나가 단일 세션 슬롯을 점유해 뒤가 전부 대기. sweep이 가사 상태.
- 요금 고갈 후 API가 403이 아니라 **HTTP 200 + 빈 body**로 "성공"을 사칭. 예산 투입 전 "내용 비어있지 않음"을 강제 검증.
